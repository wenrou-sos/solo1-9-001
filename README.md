# 水文监测数据校核工作台

本地运行的水文数据校核工具：导入 CSV → 自动校核找出可疑数据 → 人工确认处理（保留/改值/无效/插值）→ 留痕可撤销 → 导出原始或修订数据。

- **前端**：React 18 + TypeScript + Vite（过程线、问题列表、记录明细联动定位）
- **后端**：Python 3.9+ / FastAPI
- **数据库**：SQLite（文件位于 `data/hydro.db`，原始值永不覆盖）

## 一、启动

### 方式 A：一键启动（推荐）

```bash
./start.sh
```

首次运行会自动创建 Python 虚拟环境、安装依赖、导入 3 个站点的样例数据，
然后启动后端（http://localhost:8000）和前端（http://localhost:5173 ）。
浏览器打开 **http://localhost:5173** 即可。

### 方式 B：分别启动

```bash
# 1. 后端
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m app.seed          # 首次：生成并导入样例数据（加 --reset 可重置）
.venv/bin/uvicorn app.main:app --port 8000

# 2. 前端（另开一个终端）
cd frontend
npm install
npm run dev
```

> 如果 npm 全局缓存有权限问题，可用项目内缓存：
> `npm install --cache ./.npm-cache`

### 运行测试

```bash
cd backend
.venv/bin/python -m pytest tests/ -v
```

共 27 个用例，覆盖五种校核规则、多规则命中、时间间隔折算、长缺测不判连续、
站点级配置、改值/无效/保留/插值、撤销联动、重复导入检测、CSV 行级错误定位。

## 三、建议的验证流程（对应功能点）

1. **导入预览与错误定位**：「数据导入」页下载模板；可故意造一个文件
   （时间写成 `abc`、数值写成中文、指标写成「含沙量」），预览会逐行指出
   行号和原因，且无法导入。
2. **重复文件提醒**：再次选择 `backend/samples/ST01_青溪站.csv` 导入，
   页面提示该文件已导入过；需勾选“强制导入”才会重复写入（校核会再标出重复记录）。
3. **自动校核**：「校核工作台」选 ST01 / 水位，左侧问题列表可见
   变化过大、超出范围、长时间不变、重复记录；点任一问题，右侧曲线定位到对应
   时间（红色虚线），下方明细表高亮该行。注意次日 02:00 的 99 同时挂着
   「超出范围」和「变化过大」两条问题（一条记录可命中多种规则）。
4. **人工处理**：
   - 对 99 那条选「手动改值」，填 12.42 和原因 → 问题自动变“已解决”，
     明细表显示原始值 99 / 生效值 12.42 / 已修订。
   - 对某条跳变选「保留原值」，填原因（如“现场确认泄洪”）→ 问题变“已忽略”。
   - 对某条选「标记无效」→ 曲线该点变为红 ✕，且它不再参与相邻变化判断。
5. **缺测与插值**：选 ST02 / 水位。
   - 点 12:00–14:00 的短缺口 → 「查看线性插值建议」，显示两个建议补点
     （9.69 / 9.71），填原因后**确认才会应用**；补点在曲线上是青色虚线、
     明细表标记「插值」，原始值为空。
   - 点 20:00–次日 06:00 的长缺口 → 系统明确提示“超过配置上限 6，不建议插值”，
     不会默认补值。
6. **撤销与重新校核**：「处理记录 / 撤销」页可以看到每批处理（插值批次含
   多条），点撤销 → 数值/状态恢复、插值补点被删除（不会被当作原始观测）、
     相关问题自动重新出现。刷新页面后处理记录仍在（持久化在 SQLite）。
7. **配置生效**：「规则配置」页把 ST01 水位的“每采样间隔最大变化量”调大到 5，
   保存后自动重新校核，原来的跳变问题消失；调回 0.5 又出现。
8. **导出**：「处理记录 / 撤销」页底部：
   - 选「修订数据」下载：含质量标记列（原始 / 人工修订 / 插值(人工补值,非原始观测) /
     无效 / 保留原值(人工确认)）和处理原因；
   - 选「原始数据」下载：只有原始观测，人工补的插值点不出现。

## 四、校核规则说明

所有规则按 **站点 + 指标** 独立计算，水位与流量互不混淆；阈值可按站点+指标配置
（「规则配置」页），未配置时用默认值。

| 规则 | 判定逻辑 |
|---|---|
| 时间缺测 | 相邻有效记录间隔 > 标称间隔 × 缺测倍数（默认 2 倍） |
| 重复记录 | 同站点、同指标、同监测时间存在多条记录 |
| 超出范围 | 生效值超出配置的合理上下限（默认水位 0–50 m，流量 0–500 m³/s） |
| 变化过大 | 相邻记录变化量 > 每间隔最大变化 × 实际间隔折算数；**长缺测两端不直接比较**，失效点也不参与邻接 |
| 长时间不变 | 连续相同值持续时长超过阈值（默认 180 分钟） |

关键设计：

- **原始数据不改动**：`raw_value` 永不被覆盖，人工结果写在 `effective_value /
  effective_status / quality_flag`；所有动作记入 `audit_log`，支持按批次撤销。
- **不自动补值**：系统只对“两端都有效、缺口 ≤ 配置上限”的短缺口给出线性插值
  **建议**，必须人工确认原因后才写入，且补点 `raw_value` 为 NULL、标记「插值」。
- **状态联动**：任何处理后自动重算受影响序列；问题消失自动置“已解决”，
  人工“已忽略/已解决”的状态不会被重算冲掉；撤销后问题重新出现。

## 五、目录结构

```
backend/
  app/
    main.py        # FastAPI 路由（导入/校核/处理/撤销/导出/配置）
    importer.py    # CSV 解析、行级校验、模板、重复文件检测
    checker.py     # 五种校核规则引擎
    actions.py     # 人工处理、审计日志、撤销、插值建议
    database.py    # SQLite 建表与连接
    seed.py        # 样例数据生成与导入
  tests/           # pytest（校核逻辑 + 修改记录/撤销）
  samples/         # 生成的样例 CSV
frontend/
  src/
    App.tsx        # 导入 / 工作台 / 配置 / 处理记录 四个页面
    TimeChart.tsx  # SVG 过程线（缺口断线、插值虚线、问题点着色、悬停定位）
    api.ts / types.ts
start.sh           # 一键启动
```
